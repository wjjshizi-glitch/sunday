# 模型参数验证方法

## 概述

火山方舟大模型支持多种生成参数，包括 temperature、top_p、max_tokens 等。验证这些参数是否生效，需要采用控制变量法，在相同条件下对比不同参数值的输出差异。

## 参数说明

| 参数 | 取值范围 | 默认值 | 作用 |
|---|---|---|---|
| temperature | [0, 2] | 1 | 控制输出随机性，值越高越随机 |
| top_p | [0, 1] | 1 | 核采样阈值，与 temperature 类似 |
| max_tokens | [1, 模型上限] | 模型默认 | 限制生成的最大 token 数 |
| presence_penalty | [-2, 2] | 0 | 惩罚已出现 token，增加话题多样性 |
| frequency_penalty | [-2, 2] | 0 | 惩罚高频 token，减少重复 |

## temperature 参数验证

### 验证原理

temperature 越低，输出越确定；temperature 越高，输出越随机。

### 验证步骤

1. **准备测试 prompt**：选择有创作空间的 prompt，例如：
   ```
   用一句话描述春天的早晨，要求包含意象和感受，不超过30字。
   ```

2. **低 temperature 测试**：
   - 设置 `temperature=0`
   - 用相同 prompt 连续调用 5 次
   - 记录每次回答

3. **高 temperature 测试**：
   - 设置 `temperature=1.5`
   - 用完全相同的 prompt 连续调用 5 次
   - 记录每次回答

4. **对比分析**：

| 观察项 | temperature=0 | temperature=1.5 |
|---|---|---|
| 5 次回答相似度 | 完全相同或仅个别字差异 | 每次都不同 |
| 用词选择 | 固定用某几个词 | 每次换不同的词 |
| 句式结构 | 基本一致 | 句式多样 |

### 判断标准

- **生效**：低 temperature 组 5 次回答高度雷同（去重后 1-2 条），高 temperature 组 5 次回答明显不同（去重后 4-5 条）
- **未生效**：两组都一样随机，或两组都完全一样

### 自动化验证脚本

使用 `scripts/validate_temperature.py` 脚本可自动完成验证：

```bash
python scripts/validate_temperature.py --api-key YOUR_KEY --endpoint YOUR_ENDPOINT_ID
```

## top_p 参数验证

### 验证原理

top_p（核采样）限制模型从累积概率超过 p 值的词汇中采样。top_p 越低，输出越确定。

### 验证步骤

与 temperature 验证类似，但需注意：
- **不要同时调整 temperature**：保持 temperature=1（默认值），只调整 top_p
- 测试 `top_p=0.1` vs `top_p=0.9`

## max_tokens 参数验证

### 验证步骤

1. 设置 `max_tokens=20`
2. 发送"写一篇 500 字的文章"
3. 观察输出是否在约 20 token 处被截断

### 判断标准

- **生效**：输出被截断，不超过 max_tokens 限制
- **未生效**：输出远超限制，或报错

## 注意事项

1. **控制变量**：每次只调整一个参数，其他参数保持默认
2. **prompt 选择**：使用有创作空间的 prompt，不要用有唯一答案的问题（如"1+1=?"）
3. **样本量**：至少调用 3 次，建议 5 次
4. **排除缓存**：如果发现两次调用结果完全相同且参数不同，可能是缓存命中，可在 prompt 末尾加时间戳绕过
5. **模型差异**：不同模型对参数的敏感度不同，部分模型在 temperature<0.1 时仍有微小随机性

## 常见问题

**Q: temperature=0 时输出仍然不完全相同？**
A: 部分模型实现中，temperature=0 并不保证完全确定性，可能存在浮点精度差异或平台侧的微小随机注入。只要"低组比高组明显更一致"就算生效。

**Q: 调整参数后输出没有变化？**
A: 检查参数是否正确传递（拼写、大小写、取值范围），确认平台是否支持该参数，部分平台可能忽略不支持的参数。
